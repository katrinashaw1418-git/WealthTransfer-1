Four categories of issues — critical data, compliance, design, and UX. Full breakdown.

---

**Critical — fix immediately**

**1. Test fixture accounts are in the client dropdown**

```
Linked Client (linkclient@example.com)
(renamed-client@example.com)
(adviser-race-1777203777300@example.com)
(adviser-ok-1777203778096@example.com)
(okadv-1777203811341@example.com)
```

Five of six clients in the dropdown are test fixtures or placeholder accounts. An adviser could create a real investment instruction against a test account. This is the same contamination issue raised across every other adviser page. Fix at the data level — test fixture accounts must not be linked to real advisers.

**2. InRange825 is in the product dropdown**

```
InRange825 — x
```

The incomplete test product with category "x" is available for selection in a live instruction form. An adviser could send a client consent request for a product with no real details. Remove InRange825 from the product shelf entirely until it has complete and accurate product information.

**3. "Linked Client" with no name is selectable**

One dropdown entry shows "Linked Client" with no display name. If an adviser selects this and sends a consent request, the client notification will address an anonymous account. Fix name resolution before this form is used.

---

**Compliance issues**

**4. Disclaimer is shown twice identically**

The "Consent recorded ≠ executed" banner appears twice at the top of the page, word for word. This looks like a rendering bug. Show it once, prominently, at the top. Repeating it does not add compliance value and looks like an error.

**5. Disclaimer wording is correct — keep it**

The content of the disclaimer is accurate and well written:

```
Consent recorded ≠ executed. When a client approves an instruction,
AMAX records the consent and audit trail. The instruction is not
placed with the fund manager and no funds move until AMAX platform
approval and execution controls are enabled.
```

Keep this exact wording. It correctly separates consent recording from execution. Do not shorten it.

**6. No suitability check before instruction creation**

The form allows an adviser to select any product for any client with no suitability check. Specifically:

- Web3 Innovation Fund (high risk, illiquid, 3-5 years) requires additional digital asset suitability assessment
- VC / Growth Equity Fund ($500K minimum, 5-7 year lock-in) requires wholesale verification
- The form has no field for suitability basis or advice record linkage

Before an instruction can be sent for client consent, the form should require:

```
Linked advice record: [select advice record or "no linked advice record"]
Suitability basis: [free text, required for high-risk products]
```

Without this, instructions are being created without documented suitability — which is a regulatory problem.

**7. "Switch" action has no source product field**

The Action dropdown includes Switch but the form has no field for "switch from which product." A switch instruction without a source product is incomplete. Either add a source product field that appears when Switch is selected, or remove Switch from the action options until the form supports it.

---

**Design issues**

**8. Page is duplicated in the paste**

The entire page content appears twice in what was shared. Confirm this is a paste issue and not an actual rendering bug in the UI. If the page is genuinely rendering twice, find and fix the duplicate component mount.

**9. Instruction table has no status filter**

There is one instruction shown (Consent recorded). As this list grows the adviser needs to filter by status:

```
[All] [Pending consent] [Consent recorded] [Approved] [Executed] [Cancelled]
```

**10. Status label "Consent recorded" needs a next-step indicator**

```
Consent recorded
```

This tells the adviser what happened but not what happens next. Add:

```
Consent recorded · Awaiting AMAX platform approval
```

The adviser should know the instruction is sitting in a queue waiting for platform approval, not that it is complete.

**11. Instruction table is missing key columns**

Current columns: Created / Client / Product / Action / Amount / Status

Add: Advice record linked / Suitability assessed / Expiry

```
Created      Client      Product              Action   Amount      Status                    Advice record
26 Apr 2026  Wise User   Web3 Innovation Fund buy      $5,000.00   Awaiting platform approval  None linked ⚠
```

The "None linked" warning flags instructions that were created without a linked advice record.

**12. Amount field has no currency selector**

```
Amount (AUD)
```

The label says AUD but the platform handles multiple currencies. If a client's portfolio is in GBP or BTC, the instruction amount may not be in AUD. Add a currency selector next to the amount field or confirm that all instructions are denominated in AUD regardless of portfolio currency.

**13. Client dropdown shows email only for some entries**

```
(renamed-client@example.com)   ← no name, just email in brackets
Wise User (wiseinvestor@amaxglobal.com.au)   ← correct format
```

All dropdown entries should follow the same format: Name (email). Entries with no resolved name should show Email only (no display name) rather than (email) with empty name field.

**14. Product dropdown shows internal category codes**

```
InRange825 — x
Premium Treasury Deposit — cash_deposit
Money Market Sweep Fund — cash_deposit
```

The category suffix is showing raw database enum values (cash_deposit, digital_assets, venture_capital, real_estate, corporate_credit). Replace with human-readable labels:

```
Premium Treasury Deposit — Cash Deposit
Money Market Sweep Fund — Cash Deposit
Web3 Innovation Fund — Digital Assets
```

**15. New instruction form needs a cancel confirmation**

The form has a Close button but no confirmation if the adviser has partially filled it. Clicking Close after selecting a client, product, and amount should prompt:

```
Discard this instruction? Your changes will not be saved.
[Discard] [Continue editing]
```
