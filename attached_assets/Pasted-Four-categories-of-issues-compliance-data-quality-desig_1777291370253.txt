Four categories of issues — compliance, data quality, design, and one product that needs immediate attention.

---

**Critical — fix before any adviser uses this page**

**1. InRange825 is incomplete and looks like test data**

```
InRange825
moderate
X          ← placeholder category
Y          ← placeholder subcategory
Target Net IRR: 8.25%
Term: 1y
Minimum: $1,000
Distributions: none
Structure: trust
Liquidity: 30d
```

Category is "X", subcategory is "Y". This is clearly a test record that was never completed. It must be either completed with real product details or removed before any adviser sees this shelf. A real adviser seeing "X" and "Y" as product categories will immediately lose confidence in the platform.

**2. High-Yield Savings Account references FDIC insurance**

```
Structure: FDIC-insured savings account
```

FDIC is the US Federal Deposit Insurance Corporation. This is an Australian platform. The correct Australian equivalent is the Financial Claims Scheme (FCS) which covers deposits up to $250,000 per ADI. Using FDIC on an Australian product is factually wrong and potentially misleading to wholesale investors. Fix to either FCS-protected or remove the insurance reference entirely if the underlying structure is not ADI-deposit-backed.

**3. Bitcoin Tracker Fund shows a target net IRR of 15.0%**

```
Target Net IRR (illustrative): 15.0%
```

The page header already says "Digital-asset strategies are a specialist sleeve and require additional suitability assessment" which is correct. But a fixed 15% target IRR on a Bitcoin tracker is misleading — Bitcoin returns are market-linked and highly variable. The landing page version of this product correctly says "Market-linked — highly variable." Fix the product shelf entry to match:

```
Target Net IRR: Market-linked — no target return
```

A fixed IRR figure on a volatile digital asset product is a regulatory problem under RG 65 and the design obligation framework.

**Data quality issues**

**4. Risk label capitalisation is inconsistent**

```
moderate    ← lowercase
Low         ← capitalised
Medium      ← capitalised
high        ← lowercase
low         ← lowercase
High        ← capitalised
```

Pick one convention and apply it to all 14 products. Recommend sentence case throughout: Low, Moderate, Medium, High.

**5. Target IRR format is inconsistent**

```
10–12%          ← range with en dash
6.2%            ← single figure
~11%            ← tilde approximation
8.5%            ← single figure
15.0%           ← trailing zero
25–35% target   ← range with the word "target" appended
4.5–5.5% p.a.   ← with p.a. suffix
3.8–4.8% p.a.   ← with p.a. suffix
2.5–3.5% p.a.   ← with p.a. suffix
```

Standardise to one format across all products. Recommend: ranges with en dash, no tilde, no trailing "target" word, p.a. suffix on all:

```
10.0–12.0% p.a.
6.2% p.a.
~11.0% p.a.
```

The inconsistency looks unprofessional and makes the shelf hard to compare across products.

**6. Term format is inconsistent**

```
2–3 years
18 months
30–39 months
~10.2 months (rolling)
24 months
~9.4 months
Open-ended
1y              ← InRange825 abbreviation
3-5 years       ← hyphen instead of en dash
5–7+ years      ← plus sign
3-year recommended hold
```

Standardise to months or years with en dashes. Remove tildes, abbreviations, and parenthetical qualifiers — put those in a notes field.

**7. Distributions format is inconsistent**

```
Monthly or quarterly
Monthly
Fixed yield + equity realisation
Quarterly
Daily accrual, monthly credit
Semi-annual distributions from DeFi yield
none            ← lowercase
None            ← capitalised
Quarterly rewards
Capital gains at exit
Income + capital gains
Capital gain at exit
```

Standardise to a short consistent label: Monthly, Quarterly, Semi-annual, At exit, None, Daily accrual.

**Design issues**

**8. No filter or sort controls**

14 products with no way to filter by asset class, risk level, minimum investment, or liquidity. An adviser looking for a low-risk short-term product has to read every card. Add:

```
[Filter: Asset class ▾]  [Filter: Risk level ▾]  [Filter: Minimum ▾]  [Filter: Liquidity ▾]
[Sort: Target IRR ▾]     [Sort: Minimum ▾]        [Sort: Term ▾]
```

**9. Cards have no consistent visual hierarchy**

Each card shows fields in slightly different orders and with different label styles. Standardise every card to this layout:

```
[Product name]              [Risk badge]
[Asset class] · [Strategy]

Target IRR    Term         Minimum      Liquidity
6.2% p.a.     18 months    $25,000      Medium

Distributions: Monthly
Structure: Fund

[Raise instruction →]
```

**10. "Raise instruction" call to action is missing**

The page header says "to allocate, raise an investment instruction with the client" but there is no button on any card to do this. Add a "Raise instruction" button to each card that opens the instruction workflow for the selected product. Even if the workflow is not fully built yet, the button should exist and either open the workflow or show a "coming soon" state.

**11. Digital assets section needs a visual separator**

The four digital asset products (Bitcoin Tracker, Diversified Crypto, Ethereum Staking, Web3 Innovation) each have the suitability warning but they are mixed in with the other products visually. Group them in a clearly labelled section:

```
─── Digital Assets ─── Specialist sleeve · Additional suitability assessment required ───
```

**12. Cash deposit products need ADI clarification**

The three cash products (High-Yield Savings, Money Market Sweep, Premium Treasury Deposit) do not clarify whether they are ADI-backed deposits or fund structures. Under Australian law this distinction matters for FCS protection and disclosure obligations. Add a one-line structure clarification to each.
