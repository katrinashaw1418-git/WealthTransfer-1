Critical fixes before running migrations
1. It creates new clients and advisers tables
Your existing AMAX app already uses users, applications, portfolios, wallets, transactions.

So this migration risks creating a parallel identity system.

Resolution:

Do not create standalone clients unless you intentionally migrate from users.

Better:

client_id → users.id
adviser_id → users.id
or add a lightweight user_roles / adviser_profiles table.

2. Enum creation is not idempotent
This will fail if rerun:

CREATE TYPE advice_source_type AS ENUM ...
Resolution:

Wrap enum creation in:

DO $$ BEGIN
  CREATE TYPE advice_source_type AS ENUM ('ai', 'adviser', 'hybrid');
EXCEPTION WHEN duplicate_object THEN null;
END $$;
Same for all enums.

3. prevent_locked_soa_edit blocks issuing the SOA
The trigger says if OLD.is_locked = true, no update is allowed. That is okay after issue.

But the API locks the SOA by updating:

SET is_locked = true, issued_at = now()
That first lock update should work.

However, later if you need to set document_url, document_hash, or final metadata after locking, it will fail.

Resolution:

Ensure all final SOA fields are saved before setting is_locked = true.

4. Fee consent validation function exists but is not attached
The migration defines:

validate_fee_consent()
but no trigger uses it.

Resolution:

Either attach it to a future fee_deductions table, or remove it for now. It currently gives false confidence.

5. fee_consent_valid may become stale
The API sets:

fee_consent_valid = true
after consent is captured.

But if consent later expires, it only changes if the daily maintenance job runs.

Resolution:

For execution, always calculate validity live from fee_consents, not only from the stored boolean.

Critical API fixes
6. Client identity is taken from request body
Many endpoints accept:

clientId
adviserId
from req.body.

That is unsafe.

Resolution:

Use authenticated session/JWT:

const clientId = req.user.id
Only admins/advisers should be allowed to act for another client.

7. No authorisation checks
The API checks whether records exist, but not whether:

client owns this advice
adviser is linked to this client
admin/compliance has permission
Resolution:

Add middleware:

requireClientOwnsAdvice
requireAdviserLinkedToClient
requireComplianceRole
8. Acceptance endpoint missing FSG checkbox
Your verified spec required:

I have received / accessed the FSG or Website Disclosure Information
The API currently has many confirmations, but not that one.

Resolution:

Add:

confirmFsgReceived
and column:

confirm_fsg_received BOOLEAN NOT NULL DEFAULT false
9. SOA viewed endpoint updates all SOA documents
This query:

UPDATE soa_documents
SET opening_screen_shown = true
WHERE advice_record_id = $1
could update older versions.

Resolution:

Update only the issued/latest SOA:

WHERE advice_record_id = $1
AND is_locked = true
ORDER BY version DESC
LIMIT 1
or store soa_document_id in the route.

Earlier spec allowed viewed/downloaded. The API gate only requires:

soa_viewed
That is acceptable if your UX forces in-app full SOA viewing. But if the full SOA is only PDF, then require soa_downloaded.

Resolution:

Choose one rule:

SOA viewed in full in-app
OR SOA downloaded
and code that explicitly.

CREATE OR REPLACE FUNCTION is_fee_consent_valid(p_advice_record_id UUID)
RETURNS BOOLEAN AS $$
DECLARE
  valid_exists BOOLEAN;
BEGIN
  SELECT EXISTS (
    SELECT 1
    FROM fee_consents
    WHERE advice_record_id = p_advice_record_id
      AND renewal_status = 'active'
      AND withdrawn_at IS NULL
      AND consent_expiry_date >= CURRENT_DATE
  )
  INTO valid_exists;

  RETURN valid_exists;
END;
$$ LANGUAGE plpgsql;
Patch F — execution gate must calculate live
CREATE OR REPLACE FUNCTION check_execution_gate()
RETURNS TRIGGER AS $$
BEGIN
  IF NEW.execution_status = 'executed' THEN
    IF NOT (
      NEW.soa_issued = true
      AND (NEW.soa_viewed = true OR NEW.soa_downloaded = true)
      AND NEW.advice_accepted = true
      AND is_fee_consent_valid(NEW.id) = true
    ) THEN
      RAISE EXCEPTION 'Execution blocked: compliance gate not satisfied.';
    END IF;
  END IF;

  RETURN NEW;
END;
$$ LANGUAGE plpgsql;

async function adviserCanAccessClient(adviserUserId: string, clientUserId: string): Promise<boolean> {
  const { rows } = await db.query(
    `SELECT 1
     FROM adviser_clients
     WHERE adviser_user_id = $1
       AND client_user_id = $2
       AND is_active = true
       AND unlinked_at IS NULL
     LIMIT 1`,
    [adviserUserId, clientUserId]
  );

  return rows.length > 0;
}

async function requireAdviceAccess(user: AuthUser, adviceRecordId: string): Promise<void> {
  const { rows } = await db.query(
    `SELECT client_id, adviser_id
     FROM advice_records
     WHERE id = $1`,
    [adviceRecordId]
  );

  if (!rows[0]) throw new Error("Advice record not found");

  const record = rows[0];

  if (user.role === "client" && record.client_id !== user.id) {
    throw new Error("Client cannot access this advice record");
  }

  if (user.role === "adviser") {
    const allowed = await adviserCanAccessClient(user.id, record.client_id);
    if (!allowed) throw new Error("Adviser is not linked to this client");
  }
}

async function checkComplianceGate(adviceRecordId: string): Promise<ComplianceGate> {
  const { rows } = await db.query(
    `SELECT 
       ar.soa_issued,
       (ar.soa_viewed OR ar.soa_downloaded) AS soa_viewed,
       ar.advice_accepted,
       EXISTS (
         SELECT 1
         FROM fee_consents fc
         WHERE fc.advice_record_id = ar.id
           AND fc.renewal_status = 'active'
           AND fc.withdrawn_at IS NULL
           AND fc.consent_expiry_date >= CURRENT_DATE
       ) AS fee_consent_valid
     FROM advice_records ar
     WHERE ar.id = $1`,
    [adviceRecordId]
  );

  if (!rows[0]) throw new Error("Advice record not found");
  return rows[0] as ComplianceGate;
}

router.post(
  "/client/advice/:adviceId/execute",
  asyncHandler(async (req: AuthRequest, res: Response) => {
    const user = requireAuth(req, res);
    if (!user) return;
    requireRole(user, ["client"]);

    const { adviceId } = req.params;
    const { executionScope, signatureName } = req.body;

    if (!signatureName) {
      return res.status(400).json({ error: "signatureName required" });
    }

    const { rows: advice } = await db.query(
      `SELECT adviser_id
       FROM advice_records
       WHERE id = $1 AND client_id = $2`,
      [adviceId, user.id]
    );

    if (!advice[0]) {
      return res.status(404).json({ error: "Advice record not found" });
    }

    const gate = await checkComplianceGate(adviceId);

    if (!gateIsSatisfied(gate)) {
      const missing = [];
      if (!gate.soa_issued) missing.push("soa_issued");
      if (!gate.soa_viewed) missing.push("soa_viewed_or_downloaded");
      if (!gate.advice_accepted) missing.push("advice_accepted");
      if (!gate.fee_consent_valid) missing.push("fee_consent_valid");

      return res.status(400).json({
        error: "Execution blocked: compliance gate not satisfied",
        missing,
      });
    }

    const { rows: exec } = await db.query(
      `INSERT INTO execution_authorisations (
        advice_record_id, client_id, adviser_id,
        authorised, execution_scope, signature_name,
        gate_soa_issued, gate_soa_viewed,
        gate_advice_accepted, gate_fee_consent_valid
      ) VALUES ($1,$2,$3,true,$4,$5,$6,$7,$8,$9)
      RETURNING *`,
      [
        adviceId,
        user.id,
        advice[0].adviser_id,
        executionScope ?? [],
        signatureName,
        gate.soa_issued,
        gate.soa_viewed,
        gate.advice_accepted,
        gate.fee_consent_valid,
      ]
    );

    await db.query(
      `UPDATE advice_records
       SET execution_status = 'executed',
           executed_at = now(),
           updated_at = now()
       WHERE id = $1 AND client_id = $2`,
      [adviceId, user.id]
    );

    await writeAuditLog("EXECUTION_AUTHORISED", {
      clientId: user.id,
      adviserId: advice[0].adviser_id,
      adviceRecordId: adviceId,
      eventData: { executionScope, gateSnapshot: gate },
      ipAddress: req.ip,
      performedByRole: "client",
    });

    res.status(201).json({
      message: "Execution authorised",
      executionAuthorisation: exec[0],
    });
