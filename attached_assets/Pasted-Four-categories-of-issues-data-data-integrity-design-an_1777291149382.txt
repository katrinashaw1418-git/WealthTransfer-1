Four categories of issues — data, data integrity, design, and compliance. Here is the full breakdown.

---

**Data problems — fix first**

**1. Assets under advice is $0 across all clients**

This is the same root cause identified on the dashboard. The real portfolio for the test client is $4.8M but every client shows $0. The AUM calculation is not pulling from the ledger. This is the most important fix on the entire adviser-facing product — an adviser looking at a $0 book when the real value is $4.8M has no usable information.

Fix: sum ledger-derived balances for all linked clients, convert to AUD using the same FX rate logic used on the client portfolio page, display with a snapshot timestamp.

**2. Test data is leaking into production-facing UI**

The top clients table shows:

```
adviser-race-1777203777300@example.com
adviser-ok-1777203778096@example.com
okadv-1777203811341@example.com
```

These are automated test fixture accounts generated by the safety test scripts. They are appearing as real linked clients in the adviser book. This is the same platform user contamination problem the CI gate tasks were built to prevent — but it is surfacing in the UI rather than the ledger.

Fix: filter out any client where email matches test fixture patterns before rendering the client book. At minimum filter emails containing `@example.com`, `__prelaunch_`, `__feegate_`, `__txsafety_`, `adviser-race-`, `adviser-ok-`, `okadv-`.

This is a data integrity issue, not just a display issue. These accounts should not be linked to a real adviser in the first place.

**3. Client names are still not resolving**

```
Linked Client        linkclient@example.com
renamed-client       renamed-client@example.com
```

The name column is showing email addresses instead of display names for most clients, and placeholder text for others. Same join problem as the workflow page. The query needs to resolve users.displayName or users.firstName + users.lastName from the adviserClients join.

**4. KYC coverage is 1 of 6 but 5 of those 6 are test fixtures**

The real KYC coverage for real clients is likely 1 of 1 or 1 of 2. Once test fixtures are filtered out this metric becomes meaningful. Right now it is measuring test account contamination, not real client KYC status.

**Design problems**

**1. $0 everywhere makes the page useless**

Once the AUM data is fixed, the layout is actually good. The structure — total AUM, avg per client, tier mix, top clients — is the right information architecture for an adviser book snapshot. Do not change the structure, fix the data.

**2. Book composition by tier**

```
Standard    5 clients · $0    0.0% of book
Professional    1 client · $0    0.0% of book
```

Once AUM is fixed, add a visual bar:

```
Standard      5 clients   AUD $X    ████████░░░░   72%
Professional  1 client    AUD $X    ███░░░░░░░░░   28%
```

The percentage split is meaningless without the bar — it reads as 0.0% for both which looks like an error even when it is not.

**3. Top clients table — add portfolio breakdown column**

Current columns: Client / Tier / Portfolio

Add: Last activity / KYC status / Fee consent status

```
Client          Tier          Portfolio    KYC        Fee consent
Wise User       Professional  $4.8M        Verified   Active · exp Aug 2026
[Next client]   Standard      $0           Pending    None
```

This gives the adviser actionable information per client rather than just a dollar figure.

**4. Average per client**

```
Avg per client $0
```

Once AUM is fixed this becomes useful. But add a note: "Excludes clients with no linked portfolio." Otherwise a book with one $4.8M client and five $0 clients shows $800K average which is misleading.

**5. Active fee consents — 2**

Good. But add which clients they belong to:

```
Active fee consents
2
Wise User · exp Aug 2026
[Client Name] · exp [date]
0 expiring ≤30d
```

An adviser should be able to see at a glance which clients have active consents without navigating to each client record.

**6. Missing: last snapshot timestamp**

The page says "read-only snapshot" but does not say when the snapshot was taken. Add:

```
Snapshot as at 27 Apr 2026 · 14:32 AEST
```

Without this the adviser does not know if they are looking at current data or data from last week.

---

**Compliance issues**

**1. Disclosures section is well written — keep it**

The disclaimer at the bottom is legally correct and appropriately cautious. Keep every word of it. The only change is formatting — make it slightly more prominent. Currently it sits below the fold and looks like fine print. It should be visible without scrolling given that it qualifies everything above it.

**2. Fee estimates section is missing**

The page description mentions "fee estimates are indicative only" but there is no fee estimate section on the page. Either add the fee estimate display with the appropriate indicative label, or remove the reference to it from the description. Referencing something that does not exist is confusing.

**3. "0.0% of book" for both tiers looks like a calculation error**

Even if assets are truly zero, showing 0.0% for both Standard and Professional tiers looks like a bug rather than an accurate reflection of a zero-AUM book. Either hide the percentage when AUM is zero and show a dash, or show client count percentage instead:

```
Standard      5 of 6 clients   83% of book by client count
Professional  1 of 6 clients   17% of book by client count
```

This is always accurate regardless of AUM.
