# 🔎 1. Critical Findings (Must Fix Before Production)

## 1.1 Fee Rule Integrity — You flagged it, but design is still unsafe

You *surface* the $150 vs $495 mismatch well, but structurally:

👉 **Current design flaw**

* Rule stores amount independently
* Consent stores amount independently
* UI warns but system still accrues ($15/day visible)

👉 **This is NOT acceptable for AFSL-grade system**

### Required fix (non-negotiable)

* **Rule.amount must NOT exist as a source field**
* It must be **derived at runtime** from consent

**Correct model**

```
fee_rule.amount := consent.amount
fee_rule.split := derived OR stored (but validated)
```

👉 Accrual engine should:

* Hard fail if mismatch detected
* Not accrue anything

Right now:

> You are accruing on invalid data → this is a **financial misstatement risk**
