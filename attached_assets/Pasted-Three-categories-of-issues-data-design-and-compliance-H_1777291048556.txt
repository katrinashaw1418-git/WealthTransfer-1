Three categories of issues — data, design, and compliance. Here is the full breakdown.

---

**Data problems — fix first**

**1. Client names are still showing as IDs and placeholders**

```
Follow up KYC for Linked Client    ← placeholder name leaking
Follow up KYC for Client #22      ← raw database ID
Follow up KYC for Client #23
Follow up KYC for Client #24
Follow up KYC for Client #26
```

Same root cause as the dashboard. The task generation is storing userId but the display query is not joining to the users table to resolve the name. Every task title should show the actual client name. This is the highest priority fix on this page.

**2. "Done" buttons on tasks that are not done**

Every task row shows a "Done" button. This implies the adviser can mark tasks complete from this view. Two questions before this ships:

First — does marking a KYC followup task as done actually update the client's KYC status or just close the task? If it only closes the task without updating KYC, an adviser could mark five KYC tasks done while the clients remain unverified. That is a compliance gap.

Second — should the adviser be able to close tasks unilaterally or should closing a KYC task require a KYC status change first? The current design allows the former. The safer design requires the latter.

**3. Task descriptions are identical for every client**

```
Client KYC status is "pending". Verify outstanding documentation
and chase the client to complete identity verification.
```

This exact text appears five times. The description should be dynamic and include what specific documentation is missing per client, not a generic template. If the system does not know what is missing, it should say "KYC incomplete — view client record for details" with a direct link.

---

**Design problems**

**1. Stat cards at the top are good — one fix needed**

The four cards are the right structure. But "Open reports — 2" is vague. Change to:

```
Pending reports
2 awaiting generation
[View reports →]
```

And add what type of reports they are if possible — portfolio report, SOA, tax summary.

**2. Task table column order is wrong**

Current order: Priority / Task / Type / Due / Action

Better order:

```
Client / Task / Type / Due / Priority / Action
```

The adviser thinks in terms of clients first, not priority levels. Client name should be the leftmost column so the adviser can scan by client.

**3. Task descriptions are too long for a workflow view**

The full paragraph description under each task makes the table hard to scan. Move the description to an expandable row or a side panel. The table row should show only:

```
[Client Name]   KYC follow-up   kyc_followup   3 May   High   [View] [Done]
```

Click to expand for the full description.

**4. "Done" button styling**

The Done button appears to already be in a completed/muted state visually based on the description. If tasks are already marked done, they should not appear in the open tasks list at all. If they are not done, the button should be a clear call to action, not muted. Clarify the state.

**5. Missing: link from each task to the client record**

Every task row needs a direct link to the relevant client. Currently an adviser seeing "Follow up KYC for Client #22" has to navigate separately to find who that is. The client name should be a clickable link that opens the client record directly.

**6. Missing: empty state for instructions**

"No instructions are currently waiting for client consent" is correct and well worded. Keep it. But add a subtle prompt:

```
No instructions waiting.
To send an investment instruction for client consent, open a client
record and use the instruction workflow.
[View clients →]
```

This tells the adviser what to do next rather than just confirming nothing is pending.

**7. Fee consents expiring — 0 is fine but add next expiry date**

```
Fee consents expiring ≤30d
0
```

When this is zero, show when the next fee consent expires even if it is outside 30 days:

```
Fee consents expiring ≤30d
0
Next expiry: 15 Aug 2026 · Wise User
```

This prevents the adviser from ignoring fee consents until they are already in the 30-day window.

---

**Compliance issues**

**1. KYC task completion must not be independent of KYC status**

As noted above — if an adviser can mark a KYC followup task as done without the client's KYC status changing to verified, the task system becomes a compliance liability. The workflow should either block task completion until KYC is verified, or require a note explaining what action was taken.

**2. Quarterly portfolio review tasks need an outcome field**

Currently the task is created and can presumably be marked done. But there is no record of what was discussed or decided in the review. For compliance the review outcome needs to be documented. Add a required notes field before a portfolio review task can be closed:

```
Before marking complete:
Review outcome notes [required]
Next review date [required]
[Save and complete]
```

**3. Task due dates are hardcoded looking**

All KYC tasks due 3 May, all portfolio reviews due 10 May. These look like they were generated in a batch on the same day rather than based on individual client timelines. Confirm the due date logic is per-client based on when their KYC was last updated or when their last review occurred — not a fixed offset from a batch run date.

---

**Priority order for fixes:**

```
1. Fix client name resolution — show real names not IDs
2. Gate KYC task completion on KYC status change
3. Add required outcome notes to portfolio review task completion
4. Add direct client links to every task row
5. Collapse task descriptions to expandable rows
6. Reorder table columns — client name first
7. Add next fee consent expiry date when count is zero
8. Add contextual prompt to the empty instructions state
```

Items 1 through 3 are correctness and compliance issues. Items 4 through 8 are UX improvements.
